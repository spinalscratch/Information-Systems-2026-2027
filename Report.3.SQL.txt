Q5. Full names of employees working in the "Sales" department

    SELECT DISTINCT e.first_name, e.last_name
    FROM employees e
    JOIN dept_emp de    ON de.emp_no = e.emp_no
    JOIN departments d  ON d.dept_no = de.dept_no
    WHERE d.dept_name = 'Sales';

    -> 51554 rows in set   (52245 different employees have worked in Sales)

Q6. Full names of male employees working in the "Finance" department

    SELECT DISTINCT e.first_name, e.last_name
    FROM employees e
    JOIN dept_emp de    ON de.emp_no = e.emp_no
    JOIN departments d  ON d.dept_no = de.dept_no
    WHERE d.dept_name = 'Finance'
      AND e.gender = 'M';

    -> 10306 rows in set

Q7. Salaries of female employees working in the "Marketing" department

    SELECT e.emp_no, e.first_name, e.last_name, s.salary, s.from_date, s.to_date
    FROM employees e
    JOIN dept_emp de    ON de.emp_no = e.emp_no
    JOIN departments d  ON d.dept_no = de.dept_no
    JOIN salaries s     ON s.emp_no  = e.emp_no
    WHERE d.dept_name = 'Marketing'
      AND e.gender = 'F';

    -> 74996 rows in set   (one row per salary period)

Q8. Full names of employees who have the same last name as their manager

    SELECT DISTINCT e.first_name, e.last_name
    FROM employees e
    JOIN dept_emp de      ON de.emp_no  = e.emp_no
    JOIN dept_manager dm  ON dm.dept_no = de.dept_no
    JOIN employees m      ON m.emp_no   = dm.emp_no
    WHERE e.last_name = m.last_name
      AND e.emp_no <> m.emp_no;

    -> 542 rows in set

    The employees table is joined twice: once as "e" (the employee) and once
    as "m" (the manager of the employee's department). e.emp_no <> m.emp_no
    removes the managers themselves. Examples from the result:

      Abdelghani Hagimont   (Development, manager DeForest Hagimont)
      Adam Alpin            (Finance,     manager Ebru Alpin)
      Adil Kieras           (Production,  manager Shem Kieras)

    The managers with the most namesakes are DeForest Hagimont (Development,
    61 employees), Krassimir Wegerle (Production, 53) and Shem Kieras
    (Production, 52).

Q9. Full names of managers who have been doing the job at least twice

    SELECT e.first_name, e.last_name, COUNT(*) AS times_manager
    FROM dept_manager dm
    JOIN employees e ON e.emp_no = dm.emp_no
    GROUP BY e.emp_no, e.first_name, e.last_name
    HAVING COUNT(*) >= 2;

    -> Empty set

    The query is correct but in this database nobody has been a manager twice:
    dept_manager has 24 rows for 24 different employees. (The primary key of
    dept_manager is (emp_no, dept_no), so a person could be manager twice only
    in two different departments, and this never happens in the data.)

===============================================================================
 Part 3 - Merging departments
===============================================================================

    Development (d005) + Research (d008) -> Research and Development (d010)
    Marketing   (d001) + Sales    (d007) -> Marketing and Sales      (d011)

Why a simple UPDATE does not work
---------------------------------
The first idea is

    UPDATE dept_emp SET dept_no = 'd010' WHERE dept_no IN ('d005', 'd008');

but it fails with

    ERROR 1062 (23000): Duplicate entry '...-d010' for key 'dept_emp.PRIMARY'

because the primary key of dept_emp is (emp_no, dept_no) and many employees
have worked in BOTH old departments (5234 people in Development and Research,
3652 in Marketing and Sales). After the UPDATE they would have two rows
(emp_no, 'd010').

Solution
--------
For every employee of the old departments insert ONE row in the new
department (from the earliest from_date to the latest to_date), then delete
the old rows and the old departments. Everything is done in a transaction so
that it is applied completely or not at all.

    START TRANSACTION;

    -- 1. new departments
    INSERT INTO departments (dept_no, dept_name) VALUES
        ('d010', 'Research and Development'),
        ('d011', 'Marketing and Sales');

    -- 2. employees
    INSERT INTO dept_emp (emp_no, dept_no, from_date, to_date)
    SELECT emp_no, 'd010', MIN(from_date), MAX(to_date)
    FROM dept_emp
    WHERE dept_no IN ('d005', 'd008')
    GROUP BY emp_no;

    INSERT INTO dept_emp (emp_no, dept_no, from_date, to_date)
    SELECT emp_no, 'd011', MIN(from_date), MAX(to_date)
    FROM dept_emp
    WHERE dept_no IN ('d001', 'd007')
    GROUP BY emp_no;

    -- 3. managers
    INSERT INTO dept_manager (emp_no, dept_no, from_date, to_date)
    SELECT emp_no, 'd010', MIN(from_date), MAX(to_date)
    FROM dept_manager
    WHERE dept_no IN ('d005', 'd008')
    GROUP BY emp_no;

    INSERT INTO dept_manager (emp_no, dept_no, from_date, to_date)
    SELECT emp_no, 'd011', MIN(from_date), MAX(to_date)
    FROM dept_manager
    WHERE dept_no IN ('d001', 'd007')
    GROUP BY emp_no;

    -- 4. remove the old rows and the old departments
    DELETE FROM dept_emp     WHERE dept_no IN ('d001', 'd005', 'd007', 'd008');
    DELETE FROM dept_manager WHERE dept_no IN ('d001', 'd005', 'd007', 'd008');
    DELETE FROM departments  WHERE dept_no IN ('d001', 'd005', 'd007', 'd008');

    COMMIT;

(The foreign keys of dept_emp and dept_manager are ON DELETE CASCADE, so
deleting the departments would also delete their rows automatically; the
explicit DELETEs just make it clearer.)

Limits of this solution
-----------------------
- Each merged department now has two current managers (to_date 9999-01-01).
  The company must choose one and close the other, e.g.
      UPDATE dept_manager SET to_date = CURDATE()
      WHERE dept_no = 'd010' AND emp_no = <the one who leaves>;
- An employee who moved Development -> other dept -> Research gets one
  continuous period in d010; the gap is lost. To keep the full history one
  would need a primary key that includes from_date.
- The history of salaries and titles is not affected (those tables do not
  reference departments).
